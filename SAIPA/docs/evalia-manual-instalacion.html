0. Escenarios de despliegue

EVAL-IA es un plugin local de Moodle que depende funcionalmente de un motor RAG (saipa-engine) para la generación de rúbricas, preguntas y la corrección asistida por IA. La instalación varía según si ese motor ya está operando para el plugin SAIPA o si debe desplegarse por primera vez.

NOTA EVAL-IA no requiere tener local_saipa instalado. Comparte únicamente el motor Python. Si SAIPA ya está en producción, EVAL-IA reutiliza las mismas credenciales de engine que SAIPA registró en la configuración global.

0.1 Escenario A — EVAL-IA sobre engine SAIPA existente

Es el camino más corto: la institución ya tiene saipa-engine levantado (con Ollama, ChromaDB y, opcionalmente, XGBoost). Instalar EVAL-IA se reduce a tres pasos:

  1. Verificar que el engine responde /health con status: ok.
  2. Subir el ZIP de local_evalia via la pantalla Installing plugins de Moodle.
  3. Completar el Setup Wizard de EVAL-IA (detecta automáticamente la config de SAIPA).

0.2 Escenario B — Despliegue nuevo del engine

Si la institución solo desea EVAL-IA (sin el módulo de detección de abandono de SAIPA), igualmente debe desplegar saipa-engine porque es el componente que contiene el pipeline RAG, el embedder y la conexión a Ollama. El procedimiento es idéntico al descrito en el Manual de Instalación SAIPA — Secciones 3 y 4, excepto que las variables de TELEGRAM_* y WHATSAPP_* pueden quedar vacías.

IMPORTANTE Sin un motor saipa-engine operativo, EVAL-IA queda en modo read-only: el plugin se instala y muestra su UI, pero todas las operaciones de IA (generar rúbrica, generar preguntas, corregir ensayos) fallarán con un error de conexión al engine.

0.3 Árbol de decisión

1. Introducción

1.1 Propósito y alcance

EVAL-IA es un plugin local para Moodle 4.4+ que asiste al docente en todo el ciclo de evaluación formativa y sumativa:

  • Generación de rúbricas a partir del material del curso indexado.
  • Generación de banco de preguntas (selección múltiple, verdadero/falso, numérica, respuesta corta, ensayo) derivadas de la rúbrica.
  • Exámenes únicos por estudiante: cada alumno recibe una combinación distinta del banco.
  • Corrección asistida por IA: para preguntas de ensayo el LLM produce una nota preliminar y justificación, que el docente valida o ajusta.
  • Publicación en gradebook: las notas finales se envían al libro de calificaciones de Moodle como ítem manual.
  • Legajos y observaciones: registro por alumno de observaciones pedagógicas exportables a CSV.

1.2 Audiencia objetivo

Este manual asume:

  • Administradores de Moodle con acceso root al servidor o al contenedor Docker.
  • Conocimiento básico de Docker Compose, HTTP/TLS y bash.
  • Familiaridad con el ciclo install plugin → upgrade.php → purge caches de Moodle.

1.3 Relación con SAIPA

EVAL-IA y SAIPA son plugins independientes que comparten el mismo motor saipa-engine. Pueden coexistir en la misma instalación de Moodle sin conflictos:

  • SAIPA se enfoca en la prevención del abandono: detección de riesgo (XGBoost), chat RAG, alertas proactivas por Telegram/WhatsApp.
  • EVAL-IA se enfoca en la evaluación asistida: rúbricas, preguntas, corrección de ensayos, publicación en gradebook.

La colección ChromaDB course_{id} indexada por uno de los plugins es reutilizada automáticamente por el otro.

2.4 Puertos de red

EVAL-IA no abre puertos propios. Reutiliza la comunicación HTTP(S) que el plugin Moodle ya establece con el engine (típicamente 8052 en la red Docker interna, o el dominio público TLS expuesto por Nginx — ver Manual SAIPA §10).

3. Preparación del entorno

3.1 Verificación del motor existente (Escenario A)

Si el engine ya está corriendo para SAIPA, ejecute desde el servidor Moodle:

curl -s http://localhost:8052/health | python3 -m json.tool

La respuesta esperada es:

{
  "status": "ok",
  "components": {
    "ollama":   "ok",
    "chromadb": "ok",
    "moodle":   "ok"
  },
  "version": "0.2.0"
}
OK Si recibe status: ok en los tres componentes, puede saltar directamente a §4 — Instalación del plugin.

3.2 Despliegue del motor desde cero (Escenario B)

Siga el Manual de Instalación SAIPA — §3 Preparación del entorno y §4 Despliegue del motor. Para una instalación exclusivamente EVAL-IA puede:

  • Dejar vacías las variables TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_URL.
  • Omitir el contenedor evolution-api del docker-compose.yml.
  • Mantener obligatorios: MOODLE_URL, MOODLE_TOKEN, OLLAMA_HOST, CHROMA_PATH.

3.3 Obtención del token de Moodle

EVAL-IA reutiliza el mismo token de servicio web que el engine usa para SAIPA. Si no existe, créelo:

  1. Site administration → Server → Web services → Manage tokens.
  2. Botón Add. Seleccione el usuario de servicio (ej. saipa_ws_user) y el servicio External services: SAIPA API (o créelo si no existe).
  3. Copie el token generado y péguelo en docker/saipa-engine.env como MOODLE_TOKEN=....
  4. Reinicie el engine: docker compose up -d --force-recreate saipa-engine.

4. Instalación del plugin local_evalia

4.1 Descarga del paquete

Obtenga el ZIP distribuido por Schaller & Ponce (local_evalia-0.4.8.zip) o clone el repositorio privado si su licencia lo permite. El ZIP contiene únicamente la carpeta local_evalia/, tal como Moodle lo espera.

4.2 Instalación vía interfaz web

  1. Inicie sesión como Site administrator.
  2. Vaya a Site administration → Plugins → Install plugins.
  3. Arrastre el ZIP o haga click en Choose a file y seleccione local_evalia-0.4.8.zip.
  4. Botón Install plugin from the ZIP file.
  5. Moodle valida el paquete; confirme con Continue.
  6. En la pantalla de Plugins check verifique que aparece local_evalia como NEW.
  7. Botón Upgrade Moodle database now. Espere el mensaje Success.

4.3 Instalación vía CLI (recomendada para producción)

# 1. Copiar el plugin a la ruta correcta
cd /var/www/html/local
unzip /tmp/local_evalia-0.4.8.zip
chown -R www-data:www-data evalia

# 2. Ejecutar upgrade sin intervención
cd /var/www/html
sudo -u www-data php admin/cli/upgrade.php --non-interactive

# 3. Purgar cachés
sudo -u www-data php admin/cli/purge_caches.php
DOCKER En entornos Docker (imagen bitnami/moodle u oficial), reemplace las rutas por docker exec saipa-moodle php /var/www/html/admin/cli/upgrade.php --non-interactive.

5. Setup wizard de EVAL-IA

Tras la instalación, EVAL-IA provee un asistente de configuración en siete pasos que valida la conexión al engine y deja listas las credenciales. Está disponible en: 

https://<su-moodle>/local/evalia/setup.php

5.1 Acceso al asistente

Ingrese como administrador. El wizard aparece automáticamente la primera vez que se visita cualquier página de EVAL-IA si la configuración global está vacía. También es accesible desde Site administration → Plugins → Local plugins → EVAL-IA → Setup Wizard.

5.2 Pasos 1 a 7

  1. Bienvenida — Resumen de funcionalidades. Botón Comenzar.
  2. Requisitos — Chequeo de Moodle 4.4+, PHP 8.1+, extensiones curl/json. Fallas deben resolverse antes de continuar.
  3. Modo de IA — Tres opciones: saipa-engine local, engine remoto (TLS), compartir config con local_saipa. Esta última sólo aparece si SAIPA está instalado.
  4. Conexión al engine — Formulario con URL base, token de servicio, y modelo LLM preferido. Botón Probar conexión dispara un GET /health en tiempo real.
  5. Canal de notificaciones OPT — Configuración del bot Telegram para enviar a los alumnos el aviso de corrección publicada. Puede saltarse.
  6. Prueba final — Ejecuta un smoke test: genera una rúbrica de 3 criterios sobre un texto embebido de prueba y verifica que el LLM responde correctamente.
  7. Finalización — Confirmación visual. Botón Ir al panel docente.
OK Al completar los 7 pasos, la configuración queda persistida en mdl_config_plugins bajo el componente local_evalia y en evalia_settings.

6.3 Creación automática de ítems de calificación

Cuando un docente publica el resultado de un examen, EVAL-IA crea (o reutiliza) un ítem manual en el gradebook del curso con idnumber = evalia_exam_{examid}. No es necesario crearlo manualmente. Para que funcione:

  • El curso debe tener el gradebook habilitado (estado por defecto).
  • El rol del docente debe tener moodle/grade:manage — incluido por defecto en editingteacher.

7. Indexación del primer curso

EVAL-IA requiere que el material del curso esté indexado en ChromaDB antes de poder generar rúbricas o preguntas. Este paso lo realiza el engine, pero se dispara desde la interfaz de EVAL-IA.

7.1 Requisitos del material

  • Los recursos soportados son: Page, File (PDF, DOCX, TXT, MD), Book, Label (texto plano).
  • Los PDFs escaneados sin OCR no se indexan: el engine los ignora silenciosamente.
  • El tamaño máximo por archivo está definido por PHP upload_max_filesize; 50 MB es suficiente en la mayoría de los casos.

7.2 Disparo manual de indexación

  1. Ingrese al panel docente: /local/evalia/teacher.php?courseid={id}.
  2. Tab Indexación. Verá la lista de recursos detectados y su estado (pendiente, indexado, error).
  3. Botón Indexar curso. El engine procesa los recursos en background; la página muestra un spinner con progreso.
  4. Cuando finaliza, cada recurso pasa a estado indexado con número de chunks generados.

7.3 Estado y reintento

Si un recurso falla (típicamente por un PDF corrupto o sin texto extraíble), se puede reintentar individualmente con el botón 🔄 junto al recurso. El log completo está en el engine: 

docker logs saipa-saipa-engine --tail 50 | grep -i "index"

8. Flujo de trabajo EVAL-IA

Esta sección presenta el ciclo completo de evaluación tal como lo ve el docente. El manual de usuario detallado queda fuera del alcance de este documento de instalación, pero esta referencia rápida permite verificar que cada etapa funciona end-to-end.

8.1 Paso 1 — Generación de rúbrica con IA

Tab Rúbricas → botón Generar con IA. El docente especifica:

  • Alcance: tema, unidad o curso completo.
  • Fuentes: checklist de recursos indexados a considerar (si omite, usa todo).
  • Cantidad de criterios: típicamente 4–8.
  • Niveles de desempeño: por defecto 4 (insuficiente / básico / competente / avanzado).

El engine responde en 5–30 s con una rúbrica editable. El docente puede ajustar cada celda antes de guardar.

8.2 Paso 2 — Banco de preguntas

Tab Preguntas. Partiendo de una rúbrica guardada, el docente solicita al motor que genere N preguntas por cada criterio, en los tipos soportados:

TipoCorrecciónNotas
Selección múltiple (MC)Automática1 correcta, 3 distractores generados por LLM.
Verdadero / FalsoAutomáticaAfirmaciones sobre el material indexado.
NuméricaAutomáticaCon tolerancia configurable.
Respuesta cortaAutomática (match) + revisión manualComparación case-insensitive con alternativas.
EnsayoIA + validación docenteVer §8.4.

Tabla 4. Tipos de preguntas soportados.

8.3 Paso 3 — Exámenes únicos por estudiante

Tab Exámenes. Al crear un examen, EVAL-IA pide: cantidad de preguntas, tipos permitidos, duración, ventana de disponibilidad. Al publicar el examen, el plugin genera una combinación única del banco por cada estudiante matriculado con rol student, evitando que dos alumnos reciban el mismo set.

8.4 Paso 4 — Corrección asistida por IA

Para preguntas de ensayo, al cerrar el examen el docente accede al panel de corrección. Para cada respuesta, EVAL-IA solicita al engine una nota preliminar (0–100) con justificación y citación de la fuente indexada. El docente puede:

  • Aceptar la nota de la IA tal cual.
  • Ajustarla con un slider y dejar un comentario adicional.
  • Rechazar la sugerencia y corregir manualmente.
IMPORTANTE La nota final nunca queda a cargo exclusivo del LLM. EVAL-IA exige la confirmación del docente antes de publicar al gradebook. Esto es un requisito pedagógico y de auditoría.

8.5 Paso 5 — Publicación en gradebook

Cuando todas las respuestas del examen están corregidas, el botón Publicar envía las notas al libro de calificaciones como un ítem manual. El ítem queda con idnumber = evalia_exam_{examid} para trazabilidad.

8.6 Paso 6 — Legajos y observaciones

Tab Legajos. Para cada alumno, el docente puede registrar observaciones pedagógicas libres (no se envían al LLM), categorizadas por tipo (académica, conductual, seguimiento). Las observaciones son exportables a CSV para su uso por el equipo académico.

8.7 Asistente EVAL-IA (FAB del panel docente)

En la esquina inferior derecha del panel docente de EVAL-IA (/local/evalia/teacher.php?courseid={id}) aparece un botón flotante arrastrable con un ícono 🤖. Al hacer clic se despliega un chat con el Asistente EVAL-IA, una IA entrenada para guiar al docente en cada etapa del flujo de trabajo.

El asistente puede responder preguntas como:

  • "¿Cómo genero una rúbrica que cubra solo las unidades 3 y 4?"
  • "¿Qué tipos de preguntas conviene usar para evaluación conceptual?"
  • "¿Por qué mi examen no aparece publicado en el gradebook?"
  • "¿Cómo re-indexo un PDF que subí tarde al curso?"
POSICIÓN PERSISTENTE El FAB es arrastrable y su posición se guarda en localStorage del navegador, igual que el Asistente SAIPA del panel del asesor. Si el docente lo mueve a otra esquina, queda ahí en visitas posteriores.
REQUIERE ENGINE ACTIVO El asistente usa el endpoint /chat/evalia del saipa-engine. Si el engine está caído o mal configurado, el FAB sigue apareciendo pero devuelve un error al enviar mensajes. Verifique la conexión en §5.2 (Wizard Paso 4) o §9.1 (Health check).

Requisitos para que funcione:

  • El Setup Wizard (§5) debe estar completado con el engine respondiendo status: ok.
  • El docente debe tener la capacidad local/evalia:manage.
  • El curso debe estar indexado (§7) para que el asistente pueda dar recomendaciones con contexto del material real.
DIFERENCIA CON SAIPA El Asistente SAIPA vive en el panel del asesor académico (visión institucional, múltiples cursos). El Asistente EVAL-IA vive en el panel docente (visión del docente, un curso a la vez). Ambos son FABs arrastrables independientes y pueden coexistir sin conflictos cuando los dos plugins están instalados.

9. Verificación post-instalación

Ejecute los siguientes tres smoke tests en orden. Todos deben pasar antes de liberar el plugin a los docentes.

9.1 Health check del engine desde Moodle

curl -s https://engine.sudominio.edu/health \
  -H "Authorization: Bearer <MOODLE_TOKEN>"

Debe retornar status: ok en los tres componentes.

9.2 Smoke test: generación de rúbrica

  1. Cree un curso de prueba con al menos un recurso tipo Page con 200+ palabras de contenido.
  2. Indéxelo (§7).
  3. Tab Rúbricas → Generar con IA → Alcance: curso completo, 4 criterios.
  4. Verifique que la rúbrica aparece en menos de 60 segundos con criterios coherentes con el material.

9.3 Smoke test: corrección de ensayo

  1. Con la rúbrica del paso anterior, genere un examen de 1 pregunta de ensayo.
  2. Desde otro navegador (o sesión incógnito) rinda el examen como estudiante de prueba.
  3. Cierre el examen desde el panel docente.
  4. Abra la corrección: debe mostrar nota sugerida por la IA con justificación citando el recurso indexado.
  5. Acepte la nota y publique al gradebook.
  6. Verifique en Calificaciones del curso que el ítem evalia_exam_{id} aparece con el valor esperado.

10. Actualizaciones de versión

10.1 Actualización del plugin

  1. Ponga Moodle en modo mantenimiento: php admin/cli/maintenance.php --enable.
  2. Respalde la base de datos (mysqldump / pg_dump).
  3. Reemplace la carpeta local/evalia/ por la nueva versión.
  4. Ejecute php admin/cli/upgrade.php --non-interactive.
  5. Purge caches: php admin/cli/purge_caches.php.
  6. Salga del modo mantenimiento: --disable.

10.2 Actualización del engine

cd /home/saipa/SAIPA/docker
git -C ../saipa-engine pull
docker compose build saipa-engine
docker compose up -d --force-recreate saipa-engine
docker logs saipa-saipa-engine --tail 30

10.3 Compatibilidad entre versiones

COMPAT EVAL-IA 0.4.x es compatible con saipa-engine 0.2.x. Consulte CHANGES.md del plugin antes de cualquier upgrade mayor para ver notas de breaking changes.

12. Seguridad y privacidad

12.1 Datos procesados por EVAL-IA

EVAL-IA envía al engine (y por lo tanto al LLM) únicamente los siguientes datos:

  • Fragmentos del material indexado del curso (públicos dentro del aula).
  • Respuestas de los estudiantes a preguntas de ensayo (para su corrección).
  • Nombres de curso y tema, sin datos personales identificables.

No se envían al LLM: nombres de alumnos, emails, direcciones IP, notas históricas, ni observaciones pedagógicas registradas en los legajos.

12.2 Privacy API de Moodle

EVAL-IA implementa el Privacy provider estándar de Moodle. Los datos que el plugin exporta ante una solicitud de derecho al olvido / portabilidad son:

  • evalia_exam_attempts — intentos del usuario.
  • evalia_exam_answers — respuestas dadas.
  • evalia_observations — observaciones donde el usuario figura como sujeto o autor.

Las rúbricas y el banco de preguntas no son datos personales (pertenecen al curso) y no se incluyen en los exports de privacidad.
